# 🛟 클로드 안전장치 키트 (Claude Safety Kit) v1.1.7

> "AI가 내 컴퓨터를 망가뜨리면 어떡하지?" — 처음 시작하는 분들의 가장 큰 불안을 없애기 위한 안전장치입니다.
> 클로드가 **되돌릴 수 없는 위험한 명령**을 실행하려 하면 자동으로 막고, **비밀키(API 키·비밀번호)가 화면에 노출**되는 것도 막습니다.

이건 백신처럼 **한 번 깔아두면 조용히 뒤에서 지켜주는** 장치예요. 평소엔 아무것도 안 하고, 위험한 순간에만 "이건 못 해요" 하고 막습니다.

**그리고 이 장치는 1회용이 아니라 여러분 컴퓨터의 "출발점"이 됩니다.** 그래서 처음부터 이렇게 만들었어요:

- 🏷️ **막을 때마다 자기 이름을 밝힙니다** — 모든 차단 메시지가 `[안전장치 v…]`로 시작하므로, 나중에 "왜 이 명령이 안 되지?" 하고 헤맬 일이 없습니다.
- 📖 **설명서가 함께 설치됩니다** — `~/.claude/hooks/SAFETY-KIT.md`. 몇 달 뒤에 봐도 이게 뭔지, 어떻게 끄는지 알 수 있어요. 클로드에게 "SAFETY-KIT.md 읽고 설명해줘"라고 해도 됩니다.
- 🧹 **한 번에 깨끗이 지워집니다** — 동봉된 `uninstall` 스크립트 하나면 훅 등록과 파일이 전부 제거됩니다.

## 무엇을 막아주나요?

**되돌릴 수 없는 파괴적 명령**
- 홈 폴더·바탕화면·문서·시스템 폴더·드라이브 전체 삭제 — `rm -rf ~`, `rm -rf "/Users/나/Desktop"`, `Remove-Item -Recurse C:\Users\...`, `rd /s C:\` 등 **따옴표를 치든, `$HOME`으로 쓰든, 경로를 풀어 쓰든** 잡아냅니다
- `format C:`, `diskpart`, `Format-Volume` — 드라이브 포맷
- `git push --force`, `git reset --hard`, `git clean -f` — 협업 기록·작업 내용 날림 (안전한 `--force-with-lease`는 허용)
- `chmod -R 777`, 포크밤, `DROP TABLE`

**비밀키 노출**
- `printenv`, `env`, `Get-ChildItem Env:` — 환경변수(비밀키 포함) 통째 출력
- `.env` 파일 열람 (`cat .env`, `Get-Content .env` 등)
- `echo $API_KEY` 같이 키를 화면에 찍는 명령
- (윈도우, v1.1.7) **비밀키 보관 폴더 `~/.secrets`** 열람 — 키를 환경변수로 불러오기와 폴더 목록 보기만 허용
- (윈도우, v1.1.7) **접속 키 폴더 `~/.ssh`·`~/.aws`** 열람·복사 (`ssh -i` 처럼 키를 쓰는 명령은 허용)
- (윈도우, v1.1.7) 클로드가 **파일 읽기 도구로 비밀키 파일을 직접 여는 것** — `.env`, `~/.secrets`, `~/.ssh`, `~/.aws`, `apikeys` 폴더 (설정의 읽기 금지 목록 `permissions.deny`)

> 💡 **비밀키는 어디에 두나요?** 홈 폴더의 `.secrets` 폴더(윈도우: `C:\Users\내이름\.secrets`)나 프로젝트의 `.env` 파일에 두세요. 클로드는 그 키를 환경변수로 쓸 수는 있지만 열어보거나 화면에 찍지는 못합니다.

**일상 작업은 건드리지 않습니다**: `npm install`, `git commit`, `rm -rf node_modules`, `rm -rf dist` 같은 프로젝트 안 정리는 그대로 됩니다.

> ⚠️ 안전장치는 "그물"이지 "방탄유리"가 아니에요. 흔한 사고를 막아주지만, 클로드가 하는 일은 늘 눈으로 확인하세요.
> 그리고 **첫 로그인과 최종 발행처럼 진짜 중요한 행동은 항상 사람이 직접** 하세요.


(또는 클로드에게 "안전장치 깔아줘"라고 말하기)

## 잘 깔렸는지 확인 (안심 테스트)

두 단계 모두 **아무것도 삭제하거나 바꾸지 않는** 안전한 테스트입니다.

**① 규칙 검사 (자가진단)** — 클로드에게:

> "안전장치 자가진단 실행해줘"

30여 개의 위험/일상 명령을 "검사만" 해보고 `🎉 전부 통과`가 나오면 규칙이 정상입니다.

**② 훅 연결 검사** — 클로드에게:

> "`git push --force` 실행해봐"

`[안전장치 v…] 강제 푸시(git push --force)를 막았어요...` 메시지가 뜨면 성공.
git 저장소가 아닌 폴더에서 하면, 설령 훅이 꺼져 있어도 명령 자체가 아무 일도 하지 않으므로 안전합니다.

> ❗ 예전 안내처럼 "바탕화면 지워줘" 같은 **진짜 위험한 요청으로 테스트하지 마세요.**
> 안전장치에 문제가 있으면 정말로 지워질 수 있습니다. 테스트는 "실패해도 무해한 명령"으로 하는 것이 원칙입니다.

## 자주 묻는 질문

**Q. 평소 작업이 느려지거나 방해받나요?**
아니요. 위험 명령이 아니면 순식간에 통과합니다. `npm install`, `git commit`, `rm -rf node_modules` 같은 일상 명령은 그대로 됩니다.

**Q. 안전장치가 정상 명령을 잘못 막으면?**
정말 그 명령이 필요하면, 클로드 말고 **직접 터미널을 열어** 실행하세요. 안전장치는 클로드의 자동 실행만 막습니다.

**Q. 뭔가 차단됐는데 이게 뭔지 모르겠어요.**
차단 메시지가 `[안전장치 v...]`로 시작하면 이 키트가 막은 것입니다. `~/.claude/hooks/SAFETY-KIT.md`에 전부 설명되어 있고, 클로드에게 "SAFETY-KIT.md 읽고 설명해줘"라고 물어봐도 됩니다.

**Q. 이걸 끄거나 지우고 싶어요.**
- 맥: `bash ~/.claude/hooks/uninstall.sh`
- 윈도우: `powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\.claude\hooks\uninstall.ps1"`

훅 등록과 파일이 전부 깨끗이 제거됩니다(다른 설정은 그대로). 제거 후 클로드를 재시작하세요.

## v1.1.7에서 바뀐 것 (Windows)

- **비밀키 보호를 키트에 넣음**: 안전장치 본체에 `~/.secrets` 폴더 규칙(이름이 나오면 막고, 환경변수로 불러오기·목록 보기만 허용 — `python -c`로 감싼 열람까지 막기 위해), `~/.ssh`·`~/.aws` 열람·복사 차단, PowerShell 쪽 빈틈(`gc env:키`, `$env:키` 그대로 출력, `ReadAllText(".env")`)을 더했다. 원래 한 사용자 컴퓨터에만 따로 걸려 있던 자격증명 보호 훅을 일반용으로 옮긴 것이다.
- **읽기 금지 목록(permissions.deny)을 설치기가 넣음**: 훅은 '명령'만 보므로, 클로드가 Read·Grep 도구로 비밀키 파일을 직접 여는 건 못 막는다. 설치기가 `.env`·`~/.secrets`·`~/.ssh`·`~/.aws`·`apikeys`에 대한 읽기·쓰기 금지 규칙을 더한다(이미 있는 항목은 그대로, 제거 시 키트가 넣은 항목만 뺌). `**/`로 시작하는 규칙은 작업 폴더 안에서만 먹어서 `//**/`(모든 드라이브) 규칙을 같이 넣는다 — 윈도우 실기기에서 실측. 단점: `.env.example`도 클로드가 열지 못한다.
- **설치기·제거기가 남의 훅을 지우던 문제 수정**: 예전엔 안전장치가 든 훅 묶음(그룹)을 통째로 바꾸거나 지워서, 같은 묶음에 직접 넣어 둔 다른 훅까지 사라졌다. 이제 묶음 안에서 안전장치 훅만 빼고 넣는다. (v1.1.6의 "같은 묶음에 다른 훅이 있으면 재설치하지 말라"는 주의는 이제 필요 없다.)
- 가짜 홈 폴더에서 시험: 기존 설정(다른 훅·allow·deny·테마) 보존, 두 번 설치해도 중복 없음, 설치된 훅의 차단 신호(exit 2), 제거 후 다른 설정 보존 — 30개 항목 통과(자가진단 67개는 별도). 새 사용자(설정 파일 없음) 설치도 확인.
- 맥(install.sh·safety-guard.sh)은 이번에 바꾸지 않았다.

## v1.1.6에서 바뀐 것

- **Windows에서 PowerShell 도구가 검사 없이 통과하던 구멍 수정**: Windows의 클로드는 Bash 도구 말고 PowerShell 도구로도 명령을 실행하는데, 훅이 `Bash`에만 걸려 있어 PowerShell 도구로 실행되는 명령은 안전장치를 거치지 않았다. 설치기와 수동 설치용 설정 조각의 matcher를 `Bash|PowerShell`로 넓혔다. 이미 설치한 분은 설치기를 다시 돌리면 반영된다. 단, 안전장치와 **같은 훅 그룹에 다른 훅을 직접 넣어 둔 경우**에는 설치기가 그 그룹을 통째로 바꾸므로, 재설치하지 말고 `settings.json`의 matcher만 `Bash|PowerShell`로 고치면 된다. (윈도우 실기기에서 실측: 넓힌 뒤 PowerShell 도구의 위험 명령이 차단됨)
- **오탐 수정**: `Get-Date -Format "h:mm tt"`처럼 PowerShell의 `-Format` 매개변수 뒤에 `글자:` 형태가 오면 드라이브 포맷(`format d:`)으로 오인하던 문제. (PowerShell 일상 명령 60여 개를 규칙에 통과시켜 찾은 유일한 오탐)
- **자가진단 보강**: PowerShell 일상 명령 15개를 "통과해야 하는 명령"에 추가.

## v1.1.5에서 바뀐 것

- **설치기 자멸 버그 수정**: 2.5단계 차단 신호 검사에서 가드가 차단 메시지를 stderr로 쓰면, `$ErrorActionPreference='Stop'`인 PowerShell 5.1이 이를 NativeCommandError로 승격시켜 설치가 중단됐다(차단이 잘 작동할수록 설치가 실패). 해당 검사 동안만 EAP를 완화. (신규 Windows 실기기 테스트에서 발견)

## v1.1.4에서 바뀐 것

- **차단 메시지 한글 깨짐 수정**: 한국어 Windows의 콘솔 출력 인코딩(CP949) 때문에 차단·안내 메시지가 깨져 보이던 문제. 가드·설치기·제거기 모두 출력을 UTF-8로 강제. (윈도우 실기기 테스트에서 발견)

## v1.1.3에서 바뀐 것

- **한국어 Windows 인코딩 수정**: Windows PowerShell 5.1은 BOM 없는 .ps1을 CP949로 읽어 한글 문자열·정규식이 깨진다. 저장소의 .ps1 파일에 UTF-8 BOM을 심고, 설치기도 다운로드·복사 후 BOM을 보장하도록 수정. (윈도우 실기기 테스트에서 발견)

## v1.1.2에서 바뀐 것

- **Windows에서 차단이 조용히 무력화되던 치명적 버그 수정**: Windows PowerShell 5.1의 `-Command`가 `& 스크립트`의 exit 2(차단 신호)를 1로 뭉개서, 맥에선 막히던 명령이 윈도우에선 그대로 실행됐다. 훅 명령 끝에 `; exit $LASTEXITCODE`를 붙여 신호를 살렸다. (윈도우 실기기 테스트에서 발견)
- **설치기에 "차단 신호 전달 검사" 추가** (맥·윈도우 공통): 등록할 훅 명령 그대로에 위험 페이로드를 흘려 exit 2가 나오는지 설치 순간에 실측 확인. 규칙 검사(자가진단)로는 못 잡는 배선 문제를 잡는다.

## v1.1.1에서 바뀐 것

- 오탐 수정: `grep -E env`처럼 명령 끝에 env/set 단어가 오는 무해한 명령을 환경변수 덤프로 오인하던 문제 (이제 env/set이 명령의 첫 단어일 때만 차단)
